# Границы production readiness

Транспортное ядро, локальная надёжность и контрактный стенд реализованы и автоматически проверяются. Для фактического ввода остаются owner/site-specific действия, которые нельзя безопасно выдумать из ТЗ:

1. Утвердить версию платформы и конфигурацию 1С.
2. Зафиксировать JSON Schema каждого command payload/result и правила проведения документов.
3. Реализовать/протестировать handlers и журнал идемпотентности в расширении 1С.
4. Утвердить OData entity mappings, source key, updated field, deletion mark и объёмы.
5. Внедрить ERP Agent API по OpenAPI в основном NestJS/PostgreSQL репозитории, включая outbox, lease fencing и idempotent ETL upsert.
6. Выдать mTLS-сертификат, настроить CA/revocation/ACL и отдельные права 1С.
7. Собрать и подписать EXE/DLL/MSI в доверенном owner-controlled CI; проверить SBOM и vulnerability scan.
8. Выполнить E2E с тестовой ERP и тестовой базой 1С, crash/timeout/load/7-day soak, затем подписать протокол приёмки.

Без пунктов 1–5 нельзя утверждать, что реальный документ уже создаётся или реальные данные ERP корректно сопоставлены. Это соответствует разделу 39 исходного ТЗ.
