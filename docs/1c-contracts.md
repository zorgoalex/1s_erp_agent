# Контракт HTTP-сервиса 1С

Обязательные endpoints относительно `.../hs/erp-integration/v1/`:

```text
GET  health
GET  capabilities
POST commands/execute
GET  commands/{commandId}
```

В расширении 1С необходим регистр с уникальным `CommandId` и полями `CommandType`, `PayloadHash`, `Status`, timestamps, `DocumentRef`, `DocumentNumber`, `ResultJson`, `ErrorCode`, `ErrorMessage`.

Алгоритм `execute` выполняется в одной максимально атомарной транзакции:

1. Найти `CommandId`.
2. При совпадающем hash вернуть сохранённый результат; при отличающемся — HTTP 409.
3. Зарегистрировать `processing`.
4. Проверить `payloadVersion` и бизнес-правила.
5. Создать/записать документ и связь `CommandId → DocumentRef`.
6. Сохранить сериализованный результат и commit.
7. Вернуть 201; бизнес-ошибку вернуть 422 с `retryable=false`.

Обработчики документов из ТЗ (`create_customer_order`, движения, поступления, списания, платёжные документы) разрабатываются отдельно под метаданные фактической конфигурации. Агент намеренно не интерпретирует бизнес-payload и не может заменить этот слой.

Перед приёмкой обязательны сценарии: одинаковый ID/одинаковый hash; одинаковый ID/другой hash; потеря ответа после commit; запрос status; неизвестная версия; бизнес-ошибка; временная блокировка базы.
