# ETL: runbook оператора

Относится к durable ETL-контуру: владение сущностями, журнал отправок, плановые запуски, ручное разрешение и сброс домена. Технические детали — в `docs/remediation/` (O1, O2, O3, R1, D1, C1).

## Главные правила

- Агент никогда не отправляет пакет повторно, если исход прошлой отправки неизвестен. Такой пакет уходит в карантин, run блокируется, а владение сущностью сохраняется до ручного разрешения.
- Watermark фиксируется только после подтверждённого ERP завершения run, одной транзакцией вместе с освобождением владения.
- Первый watermark сущности создаёт только явный полный baseline: команда ERP `start_full_sync` или `reload_entity`. Плановый incremental сущность без baseline пропускает и пишет предупреждение `ETL_BASELINE_REQUIRED`.
- Неподтверждённые файлы spool и строки SQLite вручную не удаляются.

## Ситуации

### `ETL_BASELINE_REQUIRED Entity=…`

Сущность включена в расписание, но базовой выгрузки у неё ещё нет. Это первый запуск, новая сущность или состояние после сброса домена.

Действие: в ERP выполнить `start_full_sync` для этой сущности (или `reload_entity`). После успешного завершения сущность автоматически попадёт в плановые запуски.

### Run в статусе `blocked` или `failed`

Причина хранится в `etl_runs.finalize_conflict_code`:

| Код | Смысл |
|---|---|
| `UPLOAD_OUTCOME_UNKNOWN` | Отправка пакета началась, ответа нет (таймаут, обрыв, не-2xx, падение процесса) |
| `ACK_INVALID` | ERP вернул ACK, не прошедший проверку (статус, id, checksum, число строк) |
| `UPLOAD_ATTEMPTS_EXHAUSTED` / `COMPLETION_ATTEMPTS_EXHAUSTED` | Исчерпан лимит попыток |
| `PRECHECK_ATTESTATION_CONTRADICTED` | ERP подтвердил попытку, которая считалась неотправленной; возможна двойная доставка |
| `INTERRUPTED_NO_CHECKPOINT` | Процесс остановился во время извлечения |
| `SOURCE_IDENTITY_CHANGED` | Во время извлечения изменилась идентичность источника 1С |
| `BEGIN_DOMAIN_CHANGED` / `BEGIN_DOMAIN_UNKNOWN` | Сохранённый watermark относится к другому домену (другой источник или определение) или не имеет fingerprint |
| `DISK_RESERVE` | Запись в spool упёрлась бы в резерв диска для команд |
| `LEGACY_UNRESOLVED` | Run создан старым конвейером до переключения |

Заблокированный run удерживает владение своими сущностями. Если это плановый run, он удерживает и ключ расписания, поэтому следующий плановый запуск не создаётся.

Порядок действий:

1. Остановить службу.
2. Проверить в ERP, что пришло по этому run и его пакетам (`batchId` в `etl_batches`), и решить, что делать с данными.
3. Разрешить run командой ниже. Команда работает только при остановленной службе.

```powershell
ErpOnecAgent.exe --etl-resolve-run <runId> --decision retry --operator <кто> --verification "<что проверено в ERP>" --workers-stopped
```

Значения `--decision`:
- `retry` — работу можно повторить новым запуском от зафиксированных watermarks;
- `rebaseline` — следующий запуск должен быть полным (см. сброс домена);
- `abandon` — работу не повторять.

Коды выхода:
- `0` — разрешено;
- `2` — отказ, причина напечатана;
- `3` — run уже разрешён с другими параметрами;
- `4` — файл базы агента отсутствует, хотя состояние агента было (см. «Потеря базы агента»);
- `1` — ошибка аргументов или предусловия, например служба запущена (занята блокировка экземпляра). Текст причины напечатан.

Возможные причины отказа:
- `AdmittedSendAttempt` / `BatchInFlight` — есть отправка с неизвестным исходом. Проверить, что процессы агента действительно остановлены. Запустить службу, чтобы восстановление при старте перевело такие попытки в `orphaned`, и снова её остановить.
- `LiveExtractionClaim` / `LiveCompletionClaim` / `LiveJobDispatch` — run ещё активен. Запустить службу, чтобы сработало восстановление при старте, и повторить.

Восстановление при старте (перевод незавершённых попыток в `orphaned`, блокировка прерванных run) входит в переключение на durable-конвейер (C1). До установки версии с C1 эти отказы означают, что run нужно разбирать вместе с разработчиком.

После разрешения владение освобождается, а для плановых run освобождается и ключ расписания.

### Смена домена: восстановление 1С из backup, новый `exportEpoch`, изменение определения сущности

Признак: `BEGIN_DOMAIN_CHANGED`, либо `BEGIN_DOMAIN_UNKNOWN` для строк, записанных до переключения.

1. Разрешить заблокированные run (см. выше), обычно с решением `rebaseline`.
2. Узнать поколение watermark: `SELECT entity_name, generation FROM watermarks`.
3. Сбросить домен сущности (служба остановлена):

```powershell
ErpOnecAgent.exe --etl-reset-domain <entity> --generation <N> --operator <кто> --reason "<почему>"
```

4. Запустить службу и выполнить в ERP `start_full_sync` или `reload_entity` для этой сущности.

Сброс архивирует строку watermark в `watermark_domain_resets` и удаляет её. Сброс отклоняется, если:
- сущностью владеет активный run (`EntityOwned`);
- поколение изменилось (`GenerationMismatch`);
- строки watermark для сущности нет (`WatermarkMissing`) — сбрасывать нечего, можно сразу запускать baseline.

### Идентичность источника 1С

Признак: `ETL_SOURCE_IDENTITY_NOT_MATCHED` при старте извлечения.

- `BindingMissing` / `BindingInvalid` — не настроен или некорректен `OneC:SourceBinding`.
- `EndpointMismatch` — `ODataBaseUrl` не совпадает с привязкой.
- `NotReady` — идентичность в 1С не инициализирована или заблокирована.
- `Unavailable` — временная недоступность.
- `DatabaseMismatch` / `EpochMismatch` / `EnvironmentMismatch` — подключена другая база или после восстановления сменилось поколение. Проверить, что это ожидаемо. Затем обновить привязку и выполнить сброс домена и новый baseline для всех сущностей.

### Диск

Признак: `DISK_WARNING`. Извлечение не начинается и не продолжается, пока на томе данных не останется свободным резерв для команд плюс запас на один пакет. Освободить место, не удаляя spool и базу агента.

### Потеря базы агента

Признак: служба не стартует с сообщением `SQLite database '…' is missing although agent state exists`, а служебные команды завершаются с кодом `4`. Файла `data/agent.db` нет, но есть маркер `data/agent.db.initialized`, резервные копии `data/backups/agent-*.db` или файлы spool.

Действие: восстановить базу из резервной копии (см. `docs/operations.md`). Создать новую пустую базу можно только осознанно, командой `--migrate`: при этом теряются принятые команды, результаты и watermarks.

### Сертификат mTLS

`CERTIFICATE_EXPIRING DaysThreshold=30/14` пишется с уровнем Warning, `DaysThreshold=7/3/1` — с уровнем Error, `CERTIFICATE_EXPIRED` — Critical. Сертификат заменяется с перекрытием по сроку, перед истечением текущего.
